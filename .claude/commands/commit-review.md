---

직전 커밋(`git log -1`) 이후 변경된 내용을 다음 순서로 처리하세요.

1. `git status`와 `git diff HEAD`로 변경 내역을 확인합니다. 추적되지 않는(untracked) 새 파일도 빠짐없이 포함합니다.
2. 무엇이 추가/수정/삭제되었는지 한국어로 간단히 요약합니다. 스크립트라면 어떤 동작을 하는지, 프리팹이라면 어떤 스크립트/컴포넌트와 연결되는지 짚어줍니다.
3. `CLAUDE.md`의 커밋 컨벤션(`<type>: <한국어 설명>`, type은 feat/fix/init/update/refactor/chore)과 "작업 단위" 기준에 맞춰 커밋 메시지(또는 서로 관련 없는 변경이 섞여 있다면 여러 개로 나눈 커밋 계획)를 제안합니다.
4. 제안한 메시지에 대해 사용자 확인을 받습니다. 수정 요청이 있으면 반영합니다.
5. 승인을 받은 뒤에만 관련 파일을 `git add`하고 커밋을 실행합니다. 승인 전에는 커밋하지 않습니다.

추가 지시사항이 있다면 참고하세요: $ARGUMENTS
